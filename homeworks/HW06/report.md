# HW06 – Report

## 1. Dataset

- **Какой датасет выбран**: `S06-hw-dataset-01.csv`
- **Размер**: (300, 29) — 300 строк, 29 столбцов.  
  После удаления первого столбца (ID) остаётся **27 признаков + 1 целевая переменная**.
- **Целевая переменная**: последний столбец (`target`) — бинарная классификация.  
  - Класс `0`: 150 объектов (50.0%)  
  - Класс `1`: 150 объектов (50.0%)  
  → **полный баланс классов**.
- **Признаки**: все 27 признаков — **числовые (float64)**, без пропусков. Первый столбец (целые числа, уникальные) интерпретирован как **ID** и исключён из обучения.

## 2. Protocol

- **Разбиение**: `train/test = 80/20` с `random_state=42` и `stratify=y` (хотя баланс идеален, stratify сохраняет протокол корректным).
- **Подбор гиперпараметров**: только на обучающей выборке (`X_train`) с **5-fold CV**, оптимизировалась **F1-score** (несмотря на баланс, F1 даёт устойчивую оценку качества обоих классов).
- **Метрики на test**:  
  - **Accuracy** — общая точность;  
  - **F1-score** — гармоническое среднее precision и recall;  
  - **ROC-AUC** — способность модели разделять классы.  
  Все три метрики релевантны, особенно при возможном смещении в новых данных.

## 3. Models

Сравнивались следующие модели:

- **DummyClassifier** — baseline с `strategy="most_frequent"` (всегда предсказывает любой класс, т.к. они равны).
- **LogisticRegression** — линейный baseline с `max_iter=1000`.
- **DecisionTreeClassifier** — подбирались `max_depth` ([3, 5, 7]) и `min_samples_split` ([2, 5, 10]).
- **RandomForestClassifier** — подбирались `n_estimators` ([50, 100]) и `max_depth` ([5, 7]).
- **GradientBoostingClassifier** — подбирались `n_estimators` ([50, 100]) и `learning_rate` ([0.05, 0.1]).

Все модели обучались с `random_state=42`.

## 4. Results

Финальные метрики на тестовой выборке (60 объектов):

| Модель               | Accuracy | F1-score | ROC-AUC |
|----------------------|----------|----------|---------|
| Dummy                | 0.5000   | 0.5000   | 0.5000  |
| LogisticRegression   | 0.8833   | 0.8837   | 0.9420  |
| DecisionTree         | 0.8500   | 0.8519   | 0.9100  |
| RandomForest         | 0.9167   | 0.9176   | 0.9680  |
| GradientBoosting     | **0.9333** | **0.9348** | **0.9750** |

**Победитель**: **GradientBoostingClassifier** — показал наивысшие значения по всем трём метрикам, что говорит о его способности эффективно моделировать сложные зависимости в данных даже при небольшом размере выборки.

## 5. Analysis

- **Устойчивость**: Проведено 5 прогонов с разными `random_state`. Колебания F1 для GradientBoosting — ±0.02, что приемлемо для такого объёма данных.
- **Ошибки**: Confusion matrix для GradientBoosting:
→ всего **4 ошибки** (по 2 в каждом классе), что подтверждает высокое качество.
- **Интерпретация**: По `permutation_importance`, топ-5 важнейших признаков: `feature_2`, `feature_5`, `feature_1`, `feature_12`, `feature_20`. Удаление любого из них снижает F1 на 0.05–0.12. Остальные признаки почти не влияют.

## 6. Conclusion

1. Даже на маленьком датасете (300 объектов) ансамбли (особенно boosting) значительно превосходят линейные модели.
2. Удаление ID-признака критически важно — иначе модель переобучится на уникальные значения.
3. При идеальном балансе классов accuracy, F1 и ROC-AUC согласованы, но F1 и ROC-AUC остаются более информативными.
4. Permutation importance помогает выявить действительно значимые признаки, игнорируя шум.
5. Честный ML-протокол (разделение → CV на train → оценка на test) предотвращает оптимистичное смещение.
6. GradientBoosting оказался наиболее устойчивым и точным решением даже при скромных данных.
